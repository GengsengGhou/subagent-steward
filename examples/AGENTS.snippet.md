## Subagent Steward

For substantial implementation, debugging, research, or review, use the installed `subagent-steward` skill; resolve its SKILL.md from the skill catalog. Preserve the user's primary model, effort, choices, and authorization. Under an Astra lead, capable Luna/Sol workers default to complete outcome ownership: task-relevant authorized setup, discovery and technical design, implementation through integration, tests and acceptance harnesses, in-scope repair, remote command/log follow-ups, related docs, and concise evidence. With multiple workers, name a useful execution or integration owner; respect project rules reserving work for the lead. The lead owns scope, scientific/product/architectural decisions, permissions, communication, actual-artifact acceptance, and delivery. Do not routinely duplicate execution or turn acceptance into harness creation, glue patches, or repeat testing; ordinarily return incomplete integration, checks, or docs to the same owner. Use native completion/event waits bounded by runtime and timely user-update rules; combine nonurgent corrections and avoid busy polling. Concurrent independent parent work is required only when the live tool actually requires it, including for nesting; otherwise awaiting an owner is valid. At full capacity, first reuse a suitable worker or queue work; do not terminate active tasks to free slots or bypass limits. The lead may investigate, test, implement, request review, or take over when uncertainty, risk, or practical need warrants it. Choose supported Luna/Sol models and efforts flexibly, favor Luna when both fit, and set both explicitly. Useful native nesting retains original scope, ownership, integration, and checks; no mandatory intermediary or quota applies. Skip delegation for routine conversation or tiny edits. If the skill is absent, continue with available capabilities without claiming to have loaded it.
